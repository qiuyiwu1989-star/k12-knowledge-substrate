# 005: 小学科学应用映射工作台

## 要什么
输入应用名称、年级与具体任务，召回小学科学能力并逐条核对原文，选择「前置要求 / 主要训练 / 可观察表现」关系、填写理由后确认或排除。保存、载入和导出映射项目；点击覆盖图回到对应任务与能力。同一个只读核心支持 HTTP、Node 库和现有 MCP。

## 不做什么
- 不改写底座、创建课标 ID、自动确认关系或评价学生。
- 不展示置信度与掌握分数，不把人工映射确认标为教师审定。
- 不默认调用外部模型。首版明确为字面候选召回。
- 不将 G1–G9 能力当小学精确标准。本期仅使用年级范围完整落于 G1–G6 的可引用科学记录。
- 不在本期实现远程 MCP OAuth、组织协作和学生档案。

## 验收清单
- [x] 只召回科学、未弃用、可引用、包含目标年级且范围在 G1–G6 的节点。
- [x] 每个候选带出处、verifiedBy、粒度、原文/推导区分、数据版本与指纹。
- [x] 1–8 个任务分别召回；空结果、错误年级、过长输入有明确反馈。
- [x] 确认需关系、任务原文摘录、理由；排除不计覆盖。
- [x] 修改输入后旧结果不能混入新任务；保存核验 ID、年级、出处和版本。
- [x] 保存、读取、导入导出可用；异会话不可读写，修订冲突不覆盖。
- [x] npm run workbench-test 覆盖真实 HTTP、持久化重启、MCP 握手与底座不变。
- [x] npm run check 通过，或明确区分存量阻塞。
- [x] 桌面/移动、键盘操作、节点联动、空态/错误态经浏览器验证。
- [x] PostgreSQL 部署后验证保存读回和旧首页。

## 实现约束
复用 mapper、presenter 和 citable 配置；只读核心登记防回写闸。映射项目单独持久化。写接口同源会话隔离，查询限流，监听回环，由现站 nginx 代理。
