# 001: 先修边的语义分类与重标

## 要什么

3,072 条先修边目前只有一种语义（"A 必须排在 B 之前"）且无可信度分级。
本 spec 要让每条边带上：它是哪一类关系、能不能绕过、不具备前置时失败长什么样、这条边有多可信。

**判据（唯一）：能否描述出，不具备 A 的孩子在 B 上失败时的具体、可观察的表现。**
描述不出来的，一律降为 `convention` 并移出推理图。

| type | 不具备 A 时 B 的失败表现 | 可绕过 | 进推理图 |
|---|---|---|---|
| `component` A 是 B 的子动作 | 会做，但某一步系统性地错，错点可定位 | 否 | 是 |
| `instrument` 做 B 时用 A 当手段 | 能到，但绕远路、很慢、用笨办法 | 是 | 是 |
| `semantic` 不懂 A 则 B 的表述无意义 | 读不懂题，答非所问，或整片空白 | 否 | 是 |
| `convention` 教材就这么排的 | 无可观测影响 | — | **否** |

## 不做什么

- 不删除任何现存边。降级为 `convention` 是打标记，不是删除。
- 不新增边。本 spec 只处理存量。

  要进行一下这个连接」）。

  撤销的理由不是「想要更多边」，是**这条承诺的依据被证伪了**：写它的时候说

## 实现约束

**两段式重标，两次独立的模型调用，顺序不可颠倒：**

第一段（不告知存在分类任务）：
> 一个完全不会「A」的孩子去做「B」，他会失败在哪一步？请描述具体的、可观察的表现。
> 如果你认为他不会失败，就直接回答「不会失败」。

第二段（只给 signature，不给上下文）：把第一段产出交给一次独立调用，按四类词表分类，并判定 strength。

理由：一次性问"这是什么类型"，模型会先选标签再倒推理由，产出的是无法证伪的标签。
第一段回答"不会失败"的，直接置为 `convention`，不进入第二段。

**管线必须增量：** 按 `hash(from_claim + to_claim)` 跳过未变更的边。全量重跑须显式 `--force-all`。
