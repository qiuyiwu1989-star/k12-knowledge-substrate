### 一条撤回的发现

这里曾经写着「**各学科的 AI 过审率和抽出来的数量成反比 —— 抽得最多的学科恰恰抽得最差**」，
并附了一张表。

**清理掉 <!--N:deprecatedAnchors-->908<!--/N--> 条劣质锚点之后，这个结论不成立了**：
数量与可用率的相关系数是 **r = +0.09**，等于没有相关。原先看到的「反比」，
是劣质锚点在少数学科里堆积造成的假象 —— 那些学科抽得多，正因为抽得烂、没被筛掉。
清掉之后，量和质就没关系了。

留着这段是因为它值得记：**在一个还在被清洗的数据集上做统计，看到的往往是清洗进度，不是规律。**

被撤回的只是那条统计规律，**具体的坑仍然真实**：科学/艺术/体育的课标【学业要求】
是大段讲态度和过程的散文，机械切分把它切成了一堆不是能力断言的碎片。艺术从 172 条
清到 <!--N:artAnchors-->116<!--/N--> 条、科学从 245 清到 <!--N:scienceAnchors-->197<!--/N--> 条，
清掉的主要就是这些碎片。

**这不是一份知识图谱。** 知识图谱是给内容打标、推题用的，要求松。这里的每一个锚点都要被
几十万条个人档案当主键引用，要求严得多——所以有一道别处没有的闸：**可判定性**。

```
[L4] 应用层    球球老师 │ 作文批改 │ 文言文 │ 诗歌 │ 课程库 │ …
                      ↓ 只允许引用 ID，禁止自造知识点
[L3] 档案层    每个孩子的掌握断言 / 兴趣 / 风格        ← 私有，不进本仓库
                      ↓ 用 L0 的 ID 做谓词
━━━━━━━━━━━━━━━━ 本仓库 ━━━━━━━━━━━━━━━━
[L2] 编排层    教材版本×年级×单元 │ 教师课程包 │ 考纲   ← 闭源（版权风险）
[L1] 映射层    2022课标条目 │ 字表词表 │ 背诵篇目
[L0] 锚点层    可判定的能力断言 + 依赖关系              ← 唯一稳定 ID 空间
```

## candidates/ 和 anchors/ 的区别

`candidates/` 是从课标机器抽出、过了可判定性闸、**但没有任何人看过**的东西。
它们有正式 ID（复核只升级状态不换 ID），但：

- `reviewStatus` 只能是 `llm-proposed` / `disputed`，标成 `*-confirmed` 会被 CI 拒
- **不能被 L3 档案引用**，也**不能建边**（给没人看过的东西建先修关系毫无意义）
- 不要求 `evidence` / `assessment` —— 那两样是复核时补的。
  硬要求只会逼人编造证据，比没有证据更糟

学科主编复核并补齐 evidence 后，搬进 `anchors/`。`manifest.json` 里的
`usableAnchors` **不算候选**——锚点数不重要，可用锚点数才重要。

## 一条铁律

**L4 的任何应用不得自己定义知识点，只能引用 L0 的 ID。**
应用发现 L0 里没有它要的锚点 → 走 `review-queue/` 申请，不许在自己库里造。
这条一破，底座立刻退化成又一个数据集，所有产品的档案重新变成互相读不懂的孤岛。

## 什么算一个锚点

判据只有一个：**能不能对一个具体孩子在某一时刻回答「会 / 不会 / 多大程度」。**

| ❌ 拒绝 | ✅ 通过 |
|---|---|
| 分数的意义 | 能在 0 到 1 的数轴上标出四分之三并说明理由 |
| 培养观察能力 | 能举例说明举头与低头的动作对比表达了什么情绪 |
| 了解古代中国的政治制度 | 能默写《静夜思》全诗且无错别字 |

左边是章节名和口号，右边是能挂档案的东西。这道闸由 `scripts/lib/decidability.mjs`
**自动执行**，在 CI 里是硬门禁——它能砍掉 LLM 批量抽取输出的 60–70%。

## 三个档位：统一的是 ID 空间，不是数据结构

硬把所有学科塞进一张先修图，是必然产出垃圾边的做法。

| 档位 | 学科 | 结构 | 允许的边 |
|---|---|---|---|
| `DAG` | 数学、物理、化学 | 先修依赖图 | hard / soft |
| `LIST` | 语文字词篇目、英语词表 | 清单 + 覆盖模型 | **不能当被修方**；可作跨学科前置 |
| `MATRIX` | 历史、地理、生物、道法、科学 | 能力维度 × 主题 | 仅 soft |

档位规则由校验器强制。LIST 档一旦当了被修方、同学科内 LIST 建了链、
或 MATRIX 档出现 hard 边，CI 直接失败。

**跨学科边**：<!--N:edges-->3069<!--/N--> 条边里只有 <!--N:crossEdges-->11<!--/N--> 条跨学科（<!--N:crossPct-->0.4<!--/N-->%，
Marble 是 5.0%）。判据比同学科严得多——必须是「学这条时现场用得到那条，用不出来就卡住」，
「都需要观察力/表达力」这种一律不算。单个前置最多被引用 6 次，防止「会使用简单的工具」
这类泛能力变成万能前置。

**这 11 条两轮重跑没变，它是对的，不是漏建。** 真正的跨学科**先修**关系本来就罕见。

「能力跨界融合」在本项目里由**另一层**表达 —— 横切维度（参照 NGSS 的 crosscutting
concepts / practices，闭合词表，<!--N:crosscuttingTagged-->1523<!--/N--> 条锚点已打标）：

| 关联类型 | 跨学科对数 |
|---|---:|
| 同一**横切概念**（找规律 / 结构与功能 / 尺度与比例 …7 个） | <!--N:crosscuttingPairs-->258921<!--/N--> |
| 同一**科学实践**（论证与设计 / 分析数据 / 探究 …8 个） | <!--N:practicePairs-->371453<!--/N--> |

**只数跨学科的对** —— 两条语文锚点都练「找规律」不算跨界。
练「找规律」的语文锚点和练「找规律」的数学锚点之间确实有关联，但那关联不是先修关系、
画不成有向边。见 [docs/crosscutting.md](docs/crosscutting.md)。

## 目录

```
candidates/<学科>.jsonl         机器抽出、过了闸、**没人看过**的候选（llm-proposed）
anchors/<学科>/<学段>.jsonl     L0 能力锚点（一行一条，可 diff、可 review、可并行改）
edges/<学科>/<学段>.jsonl       L0 先修边（仅 DAG/MATRIX 档）
lists/<清单>/<学段>.jsonl       L1 字表 / 词表 / 背诵篇目
mappings/<框架>.jsonl           L1 课标映射（自编码 + 页码 + 句子级引文）
review-queue/*.jsonl            待人工复核的候选
schema/*.schema.json            JSON Schema —— **校验器真跑它**（见下），不是文档
scripts/                        校验器 / 自测 / manifest / 导入
OWNERS.md                       每个分片的学科主编 —— 没有它就没有人 review PR
```

**为什么是 JSONL 而不是一个大 JSON**：Marble 把 1,590 条塞进一个 1.6MB 的
`topics.json`，结果 707 个 fork 一个都没合并回去——单文件在 git 里无法 diff、
PR 无法 review、两人同改必冲突。到 15,000 规模这不是性能问题，是治理问题。

## 用

```bash
npm run check      # 自测 + 生成 manifest + 全量校验（CI 就跑这个）
npm run validate   # 只校验
npm run selftest   # 证明校验器真的会拦（<!--N:selftestCases-->41<!--/N--> 条不变式）
npm run review-loop # 端到端验教师复核闭环（<!--N:reviewLoopCases-->15<!--/N--> 条断言）
```

导入诗歌资产库：

```bash
node scripts/import-shige.mjs --in <poems.jsonl> --dry-run
```

机械部分自动化（篇目清单、默写锚点），判断部分进 `review-queue/`（赏析类锚点、
缺失学段）。**学段是判断不是数据，不得从库里推断**——必须对照课标附录篇目表确认。

## 校验器管什么

除了引用完整性、无环、无重复这些常规项，这五条是本项目专属的：

1. **可判定性** —— 每个 statement 必须过滤器通过
2. **规范化** —— 全半角、零宽字符、异体字必须已归一（诗歌库踩过：同一实体在库里分裂成两条）
3. **去重签名** —— 同学科下 `(verb, object)` 不得重复（Marble 有 21 组完全同名、75 组基名冲突）
4. **档位规则** —— LIST 不建图，MATRIX 无 hard 边
5. **证据强度** —— hard 边必须有非 llm 证据；`codes-only` 来源不得附文本
6. **schema 合规** —— `schema/*.schema.json` 由 `scripts/lib/schema-check.mjs`（零依赖）
   逐条执行，字段多一个都拦。**只校验存活锚点**：弃用记录是历史，不重写历史。

   2026-08-20 之前这几个 schema 是**摆设** —— 没有任何东西校验它们，于是悄悄烂到
   「缺 9 个高中学科、缺 KNOWLEDGE 型、缺 14 个实际字段」，拿它去建模会把整个数据集
   判成非法。接上闸的第一天就抓出一个真 bug：`reviewedBy` 的正则只认 ASCII，
   **第一个签中文名的老师会被判非法**。

`npm run selftest` 会逐条注入违规数据，证明每条不变式真的会触发。
**没被验证过的校验器等于没有校验器。**

disputed 怎么落定、以及顺出来的两个静默 bug（艺术学段划分、schema 是摆设），见 [docs/disputed.md](docs/disputed.md)。

|---|---:|---|
| `auto-confirmed` | 146 | 能 |
| `ai-adjudicated` | 242 | 能（AI 裁定，**待人工异议**） |
| `expert-confirmed` | 0 | 能 |
| `ai-reviewed` | 1041 | 能（2026-08-20 起 —— **AI 看过、没挑出毛病**，不是教师签字） |
| `disputed` | 724 | **不能** —— AI 复核挑出了具体问题 |

| **存活合计** | **2158** | 其中 **1429** 可用 |<!--/N-->

各状态的含义：

- `auto-confirmed` —— 机械可判定（清单条目这类数得清的东西），不靠模型判断
- `ai-adjudicated` —— AI 裁定通过，**待人工异议**。这一档是当前可用集合的大头，
  它成立的前提是「没人反对」，不是「有人认可」
- `expert-confirmed` —— 学科主编签字。**目前 0 条**
- `ai-reviewed` —— 过了 AI 学科审查，没有被挑出问题。
  **2026-08-20 起计入可用**：教师签字通道本来就还没开，继续把这 1,015 条标成
  「不可引用」等于让底座对外没有可用规模。放宽的是「AI 看过、没挑出毛病」这一档 ——
  **不是教师签字，也没有伪造任何教师签字**。`humanConfirmedAnchors` 依然如实报 0。
  定义见 [`mappings/citable.json`](mappings/citable.json)（Node 与 Python 共读一份，
  此前它散落 8 处、三种取值）
- `disputed` —— 有争议，挂起
- `llm-proposed` —— 模型提议，无人看过

`usableAnchors` = `auto-confirmed` + `ai-adjudicated` + `expert-confirmed`。
**这是本项目唯一重要的进度指标**——锚点数不重要，可用锚点数才重要。

> ⚠️ 这个定义曾经被写成「总数 − `llm-proposed` 数」，那是错的：按那个算法，
> `ai-reviewed` 和 `disputed` 都会被算进可用集合。定义现在只写在
> `scripts/sync-docs.mjs` 一处，其余地方引用它。

## 底座现在能做什么、不能做什么

`tools/profile_demo.py` 是验收测试：模拟一个产品往档案里写断言，再从底座取回价值。

**能做——记录：**
```
能正确书写基本字表中的汉字      214 / 299   72%
能正确书写常用字表一中的汉字    386 / 2500  15%
背诵篇目                        23 / 135 篇
识字量合计 600 字（老师当面确认 6 条，其余 AI 判定待确认）
```

**半能做——推荐路径。** 这里曾经写「完全不能做」，清洗之后变了一半：

<!--N:usable-->1429<!--/N--> 条可用锚点里有 <!--N:usableMatrix-->946<!--/N--> 条 MATRIX 档，
其中 <!--N:usableEdges-->1584<!--/N--> 条边**两端都可用** —— 这些路径现在是能推的。

**但仍然不能做真正的先修推荐**，因为：

- **DAG 档（数学 / 物理 / 化学）<!--N:usableDag-->286<!--/N--> 条可用。** 189 条里 152 条只过了 AI 审查、
  29 条存疑。真正「学 B 之前必须先会 A」的那类关系，全在这一档
- 那 270 条可用边**全是 `soft`**，而且来自 `ai-adjudicated`（AI 裁定待异议）。
  能推，但推的依据是「没人反对」，不是「有人确认」
- LIST 档（字表词表篇目）是覆盖模型，本来就不该有依赖

要让「按孩子的实际状态推下一步」真正成立，必须有**可用的 DAG 锚点**。
而 DAG 锚点的判定依赖教学判断，**这是绕不过教师复核的地方**。
把它们标成 `auto-confirmed` 会破坏整个证据分级 —— 不做。

## 复核怎么闭环

```
老师标记 → 复核单/图谱导出 → tools/apply_review.py → 两个方向：
  标「学段不对/表述要改/不该收」 → disputed         → 退出可用集合
  标「成立」且**署名**            → expert-confirmed → 进入可用集合
```

- **每个能力有独立链接**：`k12.yongle.school/#ca_7Kd9mQ`。老师发现问题能直接把
  「就是这个点」发出来，不用描述半天
- **就地标记**：面板底部标整条锚点（学段不对 / 表述要改 / 不该收 / 缺前置），
  每条直接前置旁边标「✕ 不对」。存在浏览器本地，攒够一批导出
- **两个方向的严格程度不对称**：降级只需一个人说不对（宁可错杀）；
  升级要求署名 —— `expert-confirmed` 的含义是「有具体的人对这条负责」，
  匿名的「成立」不算签字。这条闭环由 `npm run review-loop` 的 14 条断言守着，
  **它断过一次：三处接口不对接，导致老师做完全部 411 条 humanConfirmedAnchors 仍是 0。**
- **不自动改**：老师说「学段不对」，我们不去猜正确学段是什么。
  标成 `disputed` 让它退出可用集合，等人来定。**自动改会把「有人怀疑」悄悄变成
  「有人确认」，那比不改更糟。**
- 每条标记都带 `srcPage`，能直接翻回课标原页核对

## 复核者：为什么值得干

每条锚点和边都记 `reviewedBy`。老师复核时做的判断——「这个该放三年级不是四年级」
「这条依赖不成立」「我教的时候会先讲那个」——**本身就是他的教学方法**。累到几百条，
系统能反向导出「XX 老师的教学序列」。

复核不是给项目打工，是老师在给自己建一份可迁移的教学 IP。这个字段别省。

## 隐私：L3 永不进仓库

未成年人个人信息属敏感个人信息，处理需监护人单独同意。本仓库的分层设计让这件事
变成架构问题而不是政策问题：

> **L0/L1/L2 是公共知识，零隐私。L3 是全部隐私。**
> 所以可以做到：**知识库在云上，孩子的数据一步不出校门。**

`schema/assertion.schema.json` 只定义接口契约，`.gitignore` 硬性拦截任何断言数据。

## 许可

| 层 | 许可 |
|---|---|
| L0 锚点 + 依赖图、L1 映射（数据库结构与关系） | ODbL 1.0 |
| 本项目撰写的文本（statement / reason / evidence） | CC BY-SA 4.0 |
| `provenance.srcText` 句子级课标引文 | **不属于本项目**，权利归教育部。按合理引用附带，用 `scripts/strip-srctext.mjs` 可一键剥离。详见 [PROVENANCE.md](PROVENANCE.md) |
| 课标 PDF 原件、诗文正文 | 不发 |
| L2 编排层、L3 档案 | 不在本仓库 |

开源 L0 不是慈善：**引用量就是护城河**。别人拿你的 ID 建档案，等于替你打桩，
而换掉一套被十万份档案引用的 ID 空间——连你自己都换不掉。
